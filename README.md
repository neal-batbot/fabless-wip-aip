# 序芯 · WIP 采购运营协同工作台

2026-10-01 迭代：新主页为服务端持久化 WIP 协同工作台；原版静态演示保留在 `/legacy/`。下方“原版说明”只适用于旧入口。

## 当前版本

- 七个页面：总览、WIP、订单交付、异常、投料回货、Agent运行、数据口径。
- 六个独立mock数据源：CRM、ERP/OA、晶圆、封装、测试、人工确认。所有客户/工厂/排期均模拟。
- 数据和事件保存在服务端 SQLite（本地）/D1（部署），刷新或更换浏览器不会丢失。
- 确定性计算与模拟执行器可直接使用；自然语言问答默认标注为mock关键词路由。
- `server/agent.mjs` 实现可选 TypeSafe Choice 语义路由。配置服务端 `TYPESAFE_API_KEY` 后调用真实Jev，模型只选只读工具，不产生数量或直接修改订单。本轮未设置密钥、未声称模型准确率。
- 云端Agent可调用 `/api/state`、`tick` 与 `agent_review`，用引用ID保存独立分析；所有建议需人工复核。

## 本地运行与调度

需要Node 23+（内置SQLite），首次运行 `npm ci`。

```sh
npm run dev
# http://127.0.0.1:4317
node scripts/scheduler.mjs --once
# 常驻进程每分钟检查到期任务；与浏览器是否打开无关
node scripts/scheduler.mjs
npm test
npm run build
```

本地运行环境：当前电脑、`.sites-runtime/wip.sqlite`，仅读取mock来源，通知只保存在工作台，无外发。电脑关闭/进程停止时，本地调度停止；不能称为云端常驻。部署后本地数据库与云端D1分开，不混用。

默认北京时间：每天09:00晨报、15:00急件复核；周一09:30周供需；每月5/20日10:00晶圆建议。工作台可修改时间、暂停规则和修改月采购日期。调度器会在下一个tick处理当日到期规则；同一规则同一天不重复执行。停机期间历史日不自动补跑，恢复后处理当天。部分来源失败的run可重试；完整成功的run复用结果。

## 演示闭环

1. 首页点击“测试批次延期”：SO-1001-1缺口由30,000变80,000，反查小米mock手机项目。
2. 比较加急：保存工厂接受后，本单缺口回30,000，北辰SO-1002-1产生20,000缺口。
3. 投料回货中为FT-01录入实际良品并勾选质量放行，生成FG-FT-01。原WIP关闭，不重复供给。
4. 对FG-FT-01选择订单并登记出货，观察未交余额变化；签收不再扣减余额。
5. 运行中心模拟冲突/缺报、重复上次同步键；在数据页查看隔离记录，在异常页保存反馈和复核时间。
6. WIP详情可拆并、暂停、返工、跨厂转移；投料页按PN从共享Die扣料。

`mock/` 为JSON/CSV源文件；`core/connectors.mjs` 映射供应商字段；`core/planning.mjs` 计算数量和交期；`core/engine.mjs` 管理工作流；`server/store.mjs` 保证事务与幂等。

## 云端无人值守更新协议

仅对已验证为owner-private的同一个Sites项目使用平台服务访问。未来任务通过Sites `get_site`获取当前站点及支持的服务访问凭证，不保存凭证，不把它作为任何外部源权限。

1. 读取 `GET /api/state`，确认所有来源仍为mock。
2. 使用 `POST /api/command` 执行 `{key:"cloud-tick:<北京时间分钟>",command:{type:"tick",at:"<当前ISO时间>"}}`。不修改分享权限。
3. 若模拟业务时钟已推进到未来，则不倒退业务时钟，记录原因并跳过此次tick。
4. 回读快照，用规则结果、来源时间和历史反馈判断新增/持续风险；无变化时保持安静。
5. 确有新增结论时，以独立幂等键提交 `agent_review`，包含text和已存在的evidenceIds；不覆盖确定性数量、不自动对外承诺。
6. 再次读取确认保存。临时失败用原操作键重试。授权失败报告，不扩大权限。

云端调度的实际创建状态以Sites关联任务为准；源代码本身不表示已启用云端任务。UI规则只决定收到tick时应运行什么；云端触发频率与UI规则分开配置。

## 原版说明

一个使用模拟数据的完整交互演示。纯静态 HTML/CSS/JavaScript，不调用大模型，不连接 OA、BI、微信或工厂，不发送消息或修改真实订单。所有公司、型号、日期规则及反馈均为演示设定。

## 本地运行

在本目录执行：

```sh
python3 -m http.server 4317 --bind 127.0.0.1 --directory dist
```

浏览器打开 http://127.0.0.1:4317 。ES modules 需要通过 HTTP 访问。状态只保存在当前浏览器的 localStorage 中，可用右上角重置按钮清除；演示并非多人共享后台。

## 建议的 5 分钟演示顺序

1. 首页点击「更新晨间 WIP」，查看两家工厂的模拟进度、来源和待办变化。
2. 在协同助手点击「SC6820 周五能到货 10 万颗吗？」。
3. 查看评估：可用现货 20,000、预计测试供给 50,000、到期缺口 30,000；封装正常 9/29 到货，晶圆 10/13 到货。
4. 展开「查看交期是如何推出来的」，解释已分配扣除、剩余工序、物流与质量条件。
5. 点击「确认测试档期」，保存「接受目标排期」的模拟反馈。确认任务完成，但实际开测仍有独立跟进任务。
6. 点击「比较加急方案」：将 30,000 颗提前至 9/25，会把北辰电子的 20,000 颗推迟至 9/28，模拟额外费用 1,200 元。
7. 创建加急确认任务；未收到接受结果前，原交期不变。保存工厂接受后，缺口变为 0，但 80,000 颗仍为有条件预计供给。
8. 关闭详情并点击「切换下午」。上午的关键确认进入复核；在加急任务选择「原优先级已被挤占」，缺口恢复 30,000。
9. 查看「投料与回货」：模拟新品下单及发料；模拟 8,000 颗测试厂直发，再单独登记客户签收。
10. 查看晶圆采购建议和经验规则。采购建议是独立的 11 月规划情景，保存不会创建真实订单。

支持在助手输入示例：
- SC6820 9/25 到货 5 万颗
- SC6820 下周五到货 10 万颗
- 查看 SC3215
- 今天哪些批次需要催办？

未支持的自然语言不会编造业务结果，会提示可用演示场景。

## 后续接入通用 Agent

domain.js 中的数据来源可替换为只读连接器，assess() 可迁移到可信计算服务。当前任务台账与反馈保存在浏览器；真实五人协作应迁移到统一服务，并增加身份、授权、幂等和操作回执。

当前的「接受/拒绝反馈」「投料」「直发」「签收」均显式模拟。没有真实承诺、库存预留、采购订单或客户沟通。

页面在 document.modelContext 存在时注册三个 WebMCP 工具；普通浏览器不需要该能力即可完整使用。工具可用于读取快照、计算模拟交期、记录模拟反馈。原生 WebMCP 可用性取决于浏览器；兼容注册器测试不代表已验证原生实现。
