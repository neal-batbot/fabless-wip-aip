# WIP 协同工作台：研究与实现约束

更新：2026-10-01。当前为模拟业务；所有工厂、路线、工时、良率、容量和订单均非客户生产事实。

## 官方依据

- [TSMC eFoundry](https://www.tsmc.com/schinese/dedicatedFoundry/services/eFoundry)：在线服务覆盖晶圆追踪和状态报告，支持客户物流协同。此依据支持多源接入方向，不证明本项目拥有接口权限。
- [Amkor Cloud Services](https://cloudservices.amkor.com/)：客户可见批次在工厂内的流转、封装良率和材料库存。
- [Amkor B2B 服务说明](https://amkor.com/wp-content/uploads/2018/02/eBusiness_B2B_Services_Brochure_BR002.pdf)：分别提供 Lot Status、Lot Event History、Material Supply、Assembly Yield、Cycle Time。支持按日/周/月生成报告。由此将当前状态、事件历史、良率和周期分开建模。
- [SSMC WIP](https://www.ssmc.com/Services/WIP)：向客户提供统一的全天候 WIP 查询界面。

这些公开资料证明批次可视化与报告交换的业务形式；不证明所有厂商具备相同字段、更新频率或承诺能力。

## 本项目的设计决定

五人采购运营团队以批次为协同对象，以销售订单行为交付责任对象。WIP 是未来供给；仅在良品数量确认及质量放行后成为可交付供给。预测在客户/项目/完整 PN/需求期间内冲减订单总量，已出货只冲减订单未交，不二次冲减剩余预测。

最小链路：客户—项目—完整 PN—预测版本/销售订单行—数量分配—批次/库存—出货。客户 PO 与加工采购 PO 使用不同实体及编号空间。共同 Die 并不意味着完整 PN 可以互换；替代必须有明确适用路线与批准记录。

交期采用剩余工序的排队、加工、质量、运输、工作日历逐步累加。已确认档期作为约束。缺失数据产生区间与待确认项，不用进度百分比外推。质量冻结供给不计入可承诺数量。

数据源分别模拟 CRM、ERP、封装厂、测试厂、晶圆厂及人工反馈。每次更新保留来源时间、接入时间、版本、事件键与原始证据。来源无更新与生产无移动分别生成数据异常与生产异常。冲突记录隔离，可信快照保持不变。

## 实现结构

保留旧演示作为历史入口。新 WIP 工作台以服务端持久化状态为准；浏览器只保存界面偏好。计算模块是确定性纯函数，服务层负责验证、事务、幂等、调度与审计。Agent 通过受限工具读快照、调用计算、写建议和跟进记录；本轮提供规则驱动模拟执行器及可替换模型接口，不能把规则模板称为已接入大模型。

调度配置默认北京时间 09:00 晨报、15:00 急件复核、周一 09:30 周计划、每月 5/20 日 10:00 晶圆建议。演示内可立即运行与推进模拟时钟。实际无人值守执行需验证运行环境与持久化连接，不能用页面计时器冒充后台任务。

## 待客户确认

- 各厂路线、休息日/班次、工序典型周期、排队与产能数据的可获得性。
- 数量单位、gross die/wafer、CP/封装/FT 良率口径及质量放行权限。
- 批次拆并/返工规则、工厂与原厂批次号对应关系。
- 订单分配优先级、冻结区间、允许分批交付与客户签收口径。
- 预测冲减窗口、取消订单处理、代理商授权及项目归因。
- 真实连接权限、更新频率、通知对象与系统写入边界。

## 验收证据计划

1. 延期事件实际改变订单覆盖结果，并反查客户项目；分批建议可核算。
2. 加急记录须先确认再生效，展示同一资源的被挤占订单。
3. 回货与直发使用唯一事件键与事务，供给转换不重复，出货后余额减少。
4. 过期/冲突记录不会覆盖可信状态，产生可处理异常。
5. 重复任务/并发写入无重复台账；重启后历史、未结异常和调度配置仍存在。
6. 拆并数量守恒、单位正确、冻结不可分配、共享 Die 不跨 PN 双重分配。
7. 所有页面可用，模拟标注清晰，发布后保持原站点权限。
