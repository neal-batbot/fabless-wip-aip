# WIP × AIP 工作台

2026-10-03。AIP 在本产品中特指 Agent in Process。本版使用模拟编排、真实确定性计算与 D1 / 本地 SQLite 持久化，未连接模型、企业源系统或外部消息。

## 演示路径

1. 打开 WIP × AIP 工作台，点击「新建正常场景」。独立 scenario UUID 保存于浏览器，数据保存于服务端；「回到共享台账」回到原工作区。
2. 正常场景小米 SO-1001-1 缺口 30,000。点击「模拟测试延期」后为 80,000。
3. 启动 Agent 分析。读取订单后，可逐步推进，或「自动运行至审核」。每步服务端提交成功后才展示完成标识；刷新后从已保存步骤继续。
4. 选择测试加急，查看小米缺口 80,000→30,000，北辰 0→20,000。切换工厂排期查看建议与当前、确认日期的区别。
5. 填写审批理由，模拟提交请求，再登记工厂接受、拒绝或替代日期。审批不改生产事实；只有工厂接受才更新确认计划。
6. FT-01 登记回货 49,000 并勾选放行，原 WIP 关闭，新库存产生。出货 FG-FT-01 的 49,000，订单未交降至 51,000。
7. 复核实际结果，比较预计 50,000 与实际 49,000；填写核验与交接说明。剩余 31,000 缺口生成新事项，旧事项保留证据和处理历史。

## 对象和接口

- `state.aip.cases`：关联订单、批次、触发依据、负责人、下次复核、状态、核验和历史。
- `state.aip.runs`：不可变输入快照、业务签名、步骤、工具输出、候选方案和错误。
- 候选方案嵌于运行对象，包含计划变更和所有竞争订单的前后缺口，费用未知为 null。
- `state.aip.requests`：审批方案副本、模拟提交、工厂反馈。替代日期必须重新审批，原请求保留。
- `GET /api/state?workspace=...`、`POST /api/command?workspace=...`、`POST /api/ask?workspace=...` 复用现有接口。默认 `demo`，隔离演示仅接受 `scenario-` 前缀的限定标识。
- 命令：`aip_start`、`aip_step`（index）、`aip_approve`（planId/reason）、`aip_submit`、`aip_reply`（reply/note/date）、`aip_recheck`、`aip_close`（reason），均带 caseId 和外层幂等 key。
- 沿用工作区 aggregate JSON 与事件事务，无需 D1 表迁移。旧状态读取时补充 AIP，后续命令持久化。云端原有定时任务默认操作共享台账，并复用未结事项。

## 行为边界

来源过期、隔离冲突和工具失败会保留错误并进入人工决策。业务证据变化导致审批或提交拒绝；可重新分析（会撤回尚在等待中的模拟请求）。快照采用保守全局竞争供需签名，包含业务时钟；任何相关供需变化均需重算。

WIP 的工序和 AIP 的处理状态独立。工厂回复不是实际完工，只有实际回货/出货凭证可进入核验。工厂部分接受指本轮替代日期，尚未实现部分数量的排程拆分。其他工厂仅作为待核实方向。

演示支持按日回货节点时间轴，不是有限产能 APS 求解器。双批次共享 ATE 档期是有边界的计算案例。现阶段同一个私有站点内没有企业多角色审批权限；事件具备模拟审批记录，不代表真实身份签章。多工作区不是多租户安全边界。大规模生产需规范化存储、真实系统身份授权、工厂适配与调度求解能力。

## 验证

27 项测试覆盖已有业务与 AIP 关键路径。浏览器实测：正常→延期→分析→加急审批→工厂接受→49k回货→出货→复核→结案，刷新后历史和剩余事项存在；桌面与390px窄屏标签切换正常。新增分支测试覆盖拒绝、替代日期、证据变化、步骤重放、失败恢复、工作区隔离及超时跟进。
